# RIMOS

RIMOS is a system that maps AI artifacts onto a mathematical Penrose space and stores their positions in an internal blockchain.

## One-Sentence Explanation

RIMOS takes an uploaded artifact, runs it through a deterministic mathematical pipeline, calculates its position on a Penrose map, and writes that position into a blockchain.

## What The System Does

```text
Upload Artifact
       ↓
Math Pipeline
       ↓
Calculate Map Position
       ↓
Create Blockchain Block
       ↓
Save in Chain
```

This is the core product behavior in the current codebase.

## Main Idea

The project can be understood as a GPS-like system for AI artifacts.

| Concept | Meaning |
| --- | --- |
| Penrose tiling | Global map |
| Genesis Mints | Fixed anchor points |
| Artifact | Point on the map |
| Tau vectors | Coordinates of that point |
| Blockchain | History of map positions |
| NFT | Optional certificate |

The map itself is fixed. It does not change.  
What changes over time is the number of artifact positions recorded on it.

## Penrose Map

The Penrose tiling is used as the global mathematical map.

Properties:

- infinite
- aperiodic
- mathematically consistent
- non-repeating but locally ordered

In practical terms:

```text
new artifact -> new point on the map
```

As more artifacts are processed, the map becomes denser.

## Genesis Mints

The system uses fixed reference anchors called Genesis Mints.

These anchors give the map orientation.

The current conceptual anchors are:

- fine-structure constant
- Einstein field equations
- Boltzmann entropy

Without anchors, positions would exist but would not have a stable frame of reference.

## Artifact Processing

When a file is uploaded, RIMOS runs a deterministic mathematical pipeline:

```text
Binary Data
  ↓
Godel Encoding
  ↓
p-adic structure
  ↓
NTT transform
  ↓
KAG separability
  ↓
Penrose mapping
```

This produces map-position values such as:

- `tau_vectors`
- `manifold_hash`
- `tile_hash`
- `barycentric`

These values describe where the artifact sits on the Penrose map.

## Tau Vectors

The tau vectors are the coordinates of the artifact on the Penrose map.

Example:

```text
τ1 = 0.6947
τ2 = 0.9180
τ3 = 0.3617
τ4 = 0.8492
τ5 = 0.7509
```

These values are already generated by the pipeline and exposed in the report layer.

## Internal Blockchain

The internal blockchain stores the history of artifact positions.

Important product idea:

```text
The blockchain does not store points.
The points are the blockchain.
```

That means each processed artifact becomes a block.

Example block model:

```text
Block
├ index
├ timestamp
├ artifact_hash
├ tau_vectors
├ manifold_hash
├ tile_hash
├ barycentric
├ prev_block_hash
└ block_hash
```

Chain structure:

```text
Genesis Block
     ↓
Artifact Block 1
     ↓
Artifact Block 2
     ↓
Artifact Block 3
```

Current local storage:

```text
backend/data/artifact_chain.json
```

The chain is bootstrapped with a genesis block representing the anchor layer.

## NFT Layer

The client’s model distinguishes between the internal blockchain and NFT minting:

- internal blockchain: required
- Solana / NFT certificate: optional

The NFT is not the map and not the chain.
It is only a certificate for a recorded artifact position.

## What The User Sees

The main customer-facing report is the Artifact Map Report.

The UI currently exposes:

- artifact map position
- manifold hash
- tau coordinates
- Penrose visualization
- Genesis anchors
- blockchain record
- pipeline metrics

The upload result page also shows compact map and blockchain summaries.

## Visualization

The Penrose visualization is included in the UI and report outputs.

It is useful, but secondary.

The primary system identity is:

```text
artifact -> map position -> blockchain block
```

## Current Features

- deterministic artifact processing through RIM-OS v2
- single-file, batch, and chunked upload flows
- resumable large-file upload sessions
- process-worker execution for CPU-bound audits
- map-position exposure:
  - `tau_vectors`
  - `manifold_hash`
  - `tile_hash`
  - `barycentric`
- internal blockchain record generation
- HTML, PDF, and SVG report outputs
- metadata parsing and optional signature verification
- abuse protection:
  - rate limiting
  - deduplication
  - replay detection
- optional Solana provenance certificate flow

## Main Runtime Pieces

### Backend

- `backend/rim_os_v2.py`
  Canonical deterministic math pipeline
- `backend/app/routers/upload.py`
  Single-file upload flow
- `backend/app/services/chunked_upload_service.py`
  Large-file resumable upload flow
- `backend/app/routers/report.py`
  Report retrieval and report artifacts
- `backend/app/services/artifact_chain.py`
  Local artifact-position blockchain

- `web/src/app/page.tsx`

- `web/src/app/upload/page.tsx`

## Local Setup

### Prerequisites

- Python 3.11+ recommended
- Node.js 20+ recommended
- npm

### 1. Start the backend

```powershell
cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
uvicorn app.main:app --port 8000
```

For short development cycles only:

```powershell
uvicorn app.main:app --reload --port 8000
```

Backend URL:

```text
http://localhost:8000
```

### 2. Start the frontend

```powershell
cd web
npm install
@"
NEXT_PUBLIC_API_URL=http://localhost:8000
NEXT_PUBLIC_MAX_FILE_SIZE_BYTES=10000000000
"@ > .env.local
npm run dev
```

Frontend URL:

```text
http://localhost:3000
```

## Configuration Notes

Selected defaults from `backend/app/config.py`:

- `max_file_size = 10_000_000_000`
- `chunk_size_bytes = 20 MB`
- `chunk_upload_max_concurrent = 8`
- `chunk_upload_session_ttl_seconds = 3600`
- `worker_timeout_seconds = 3600`
- `artifact_chain_path = data/artifact_chain.json`
- `validate_file_extension = true`
- `parse_metadata = true`
- `verify_signatures = true`
- `enable_rate_limiting = true`
- `enable_deduplication = true`
- `enable_replay_detection = true`

Frontend behavior:

- files `>= 100 MB` use chunked upload
- upload result page shows map snapshot and blockchain record summary
- full Artifact Map Report shows coordinates, anchors, blockchain record, and Penrose visualization

## Development Notes

- Do not casually modify `backend/rim_os_v2.py`; it is the canonical deterministic engine
- The UI should expose existing pipeline outputs, not recompute them
- The internal blockchain is file-backed today and can later be replaced by a database or distributed layer
- Solana minting is optional and should remain secondary to the internal chain
